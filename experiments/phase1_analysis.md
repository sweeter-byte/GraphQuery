# Phase 1 实验分析报告

**日期**: 2026-03-19
**实验**: E7a (搜索空间对比), E7c (S1-S4消融), E7d (cost_factor敏感度)
**数据集**: yeast, wordnet, dblp, human, youtube, patents (6个)
**每组查询数**: 50

## 1. E7a: Pruned vs Baseline 搜索空间对比

| V | 查询数 | pruned成功率 | baseline平均 | pruned平均 | baseline耗时 | pruned耗时 |
|---|--------|-------------|-------------|-----------|-------------|-----------|
| 4 | 300 | 100% | 14 | 9 | 0.00s | 0.00s |
| 8 | 600 | 100% | 50 | 454 | 0.00s | 0.04s |
| 12 | 200 | 47% | 50 | 488 | 0.00s | 0.30s |
| 16 | 600 | 1% | 50 | 500 | 0.00s | 0.72s |
| 20 | 200 | 1% | 50 | 250 | 0.01s | 0.03s |
| 24 | 400 | 0% | - | - | - | 1.26s(abort) |
| 32 | 400 | 0% | - | - | - | 1.31s(abort) |

### 关键发现

1. **V≤8: Pruned 完全可用**。V=4 时 pruned 生成更少但更精确的 order（9 vs 14），V=8 时 pruned 生成远多于 baseline（454 vs 50），因为 A* 搜索能系统性地探索空间。
2. **V=12: 分水岭**。47% 的查询 pruned 能成功（主要是 wordnet 的 V=12 查询），成功时生成 488 个 order。
3. **V≥16: Pruned 几乎完全失败**。搜索空间爆炸，200k pops 预算不够到达深度 V。Early abort 优化将无效搜索时间从 5-9s 降到 1-2s。
4. **Baseline 稳定但保守**。beam_width=50 在所有 size 上都能快速返回 50 个 order（<0.01s），但质量无法保证。

### 按数据集分析

wordnet 的成功率最高（53%），因为它有 V=12 的查询且图结构有更多对称性（S1 剪枝有效）。其余数据集成功率约 33%（仅 V=4 和 V=8 成功）。

## 2. E7c: S1-S4 消融实验

### V=4 (所有配置都成功)

| 配置 | 平均order数 | 平均耗时 |
|------|-----------|---------|
| full | 9.5 | 0.0001s |
| no_S1 | 13.6 | 0.0001s |
| no_S2 | 9.5 | 0.0001s |
| no_S3 | 9.5 | 0.0001s |
| no_S4 | 9.5 | 0.0001s |
| none | 13.6 | 0.0001s |

V=4 太小，所有策略都能瞬间完成。S1（对称性剪枝）是唯一有效果的策略——关闭后 order 数从 9.5 增加到 13.6。

### V=8 (所有配置都成功)

| 配置 | 平均order数 | 平均耗时 | 相对full耗时 |
|------|-----------|---------|------------|
| full | 453.8 | 0.035s | 1.00x |
| no_S1 | 500.0 | 0.065s | 1.89x |
| no_S2 | 455.2 | 0.034s | 1.00x |
| no_S3 | 453.8 | 0.034s | 0.99x |
| no_S4 | 453.8 | 0.033s | 0.94x |
| none | 500.0 | 0.062s | 1.79x |

S1 是最关键的策略——关闭后耗时增加 89%，order 数达到上限 500。S2/S3/S4 在 V=8 上影响很小。

### V=12 (关键分水岭)

| 配置 | 平均order数 | 平均耗时 | 成功率 |
|------|-----------|---------|--------|
| full | 229.4 | 1.46s | 47% |
| no_S1 | 0.0 | 1.42s | 0% |
| no_S2 | 223.7 | 0.16s | 46% |
| no_S3 | 229.4 | 0.14s | 47% |
| no_S4 | 228.9 | 0.13s | 47% |
| no_S3S4 | 228.9 | 0.13s | 47% |
| none | 0.0 | 1.36s | 0% |

**核心发现**: S1（对称性剪枝）是 V=12 能否成功的决定性因素。关闭 S1 后成功率从 47% 直接降到 0%。S2/S3/S4 对成功率几乎无影响，但 S3（A* 代价剪枝）显著增加了 full 配置的耗时（1.46s vs 0.14s），这是因为 S3 的代价计算本身有开销。

## 3. E7d: cost_factor 敏感度分析

### 结论

cost_factor 在 1.1 到 50.0 的范围内对结果**完全没有影响**：
- V=4: 所有 cost_factor 产生相同的 9.5 个 order
- V=8: 所有 cost_factor 产生相同的 453.8 个 order
- V=12: 所有 cost_factor 产生相同的 229.4 个 order

**原因分析**: S3 剪枝条件是 `f_score > cost_factor * best_cost`。当 best_cost 为 inf（未找到任何完整 order 时），这个条件永远不触发。当找到第一个 order 后，由于 A* 搜索的性质，后续 order 的 f_score 通常接近 best_cost，所以即使 cost_factor=1.1 也不会过度剪枝。

**建议**: cost_factor 参数可以使用默认值 1.5，无需调优。S3 策略的实际效果需要在更大的搜索空间中验证。

## 4. 总结与建议

### A* Pruned 搜索的适用范围
- **V≤8**: 完全可用，推荐使用
- **V=12**: 约 47% 成功率，可作为 fallback 前的首选
- **V≥16**: 不可用，应直接使用 baseline

### 策略重要性排序
1. **S1（对称性剪枝）**: 最关键，决定了 V≥12 能否成功
2. **S2（核心优先）**: 影响很小
3. **S3（A* 代价剪枝）**: 当前实现中反而增加开销，需要优化
4. **S4（安全性排序）**: 影响很小

### 优化建议
1. 增强 S1：改进等价类检测算法，使其在更多图结构上有效
2. 优化 S3：减少代价计算开销，或在 V≤8 时禁用 S3
3. 自适应策略：根据 V 自动选择 pruned 或 baseline
4. 增加 max_heap_pops 预算：对 V=12-16 的查询，可以尝试更大的预算（如 500k-1M）
