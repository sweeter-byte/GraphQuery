You are a data scientist working on a subgraph matching optimization project called GraphQuery. The project has three stages:

- **M1**: Generates candidate matching sequences (orderings of query graph vertices) using different (filter, order) algorithm combinations.
- **M2** (not yet built): Estimates the cost of each candidate sequence using prefix subgraph cardinality estimation, then ranks and selects the best one.
- **M3**: Runs real subgraph enumeration for each candidate sequence on multiple engines, recording actual performance (embedding count, enumeration time, etc.) as ground truth.

## Data Location

All data is under `/home/ranmaoyin/graph_query/Fastest-par/results/`:

- `m1_data/<dataset>.csv` — M1 output, one file per dataset (8 datasets: dblp, eu2005, hprd, human, patents, wordnet, yeast, youtube)
  - Columns: `dataset, query_file, query_vertices, query_edges, filter, order, sequence, filter_time, plan_time, preprocessing_time, status`
  - Each row is one candidate sequence generated by a (filter, order) combination for a specific query graph.

- `m3_data/<dataset>.csv` — M3 output, one file per dataset
  - Columns: `dataset, query_file, query_vertices, query_edges, filter, order, engine, sequence, embedding_count, total_time, enum_time, filter_time, build_table_time, plan_time, preprocessing_time, memory_mb, call_count, eps, status`
  - Each row is one real enumeration result: a specific sequence executed by a specific engine.
  - `status` values: `OK` (success), `TIMEOUT`, `CRASH:rc=1`, `CRASH:rc=-6`, `CRASH:rc=-11`
  - 7 engines: EXPLORE, LFTJ, GQL, QSI, VF3, RM, KSS

## Task

Create a Jupyter notebook `analysis/m1_m3_analysis.ipynb` that performs the following analyses. Use pandas, matplotlib, and seaborn. Make all plots publication-quality with clear labels and titles.

### Part 1: Data Overview

1. Load all M1 and M3 CSV files. Report row counts, column types, and missing values per dataset.
2. For M3 data, compute the status distribution (OK / TIMEOUT / CRASH) per dataset and per engine. Show as a heatmap table.
3. Identify which engines have the highest crash/timeout rates. Recommend which engines to exclude from further analysis.
4. For M3 OK rows, show the distribution of `enum_time` per engine (box plot or violin plot).

### Part 2: M1 Sequence Statistics

1. For each (dataset, query_file), count how many unique sequences M1 generated. Show the distribution across datasets.
2. Analyze how many distinct (filter, order) combinations produced sequences per query graph.
3. Check sequence diversity: for each (dataset, query_file), what fraction of sequences are unique vs. duplicated across different (filter, order) methods?

### Part 3: M3 Engine Performance Analysis

1. For each (dataset, query_file, sequence) with status=OK, compare `enum_time` across engines. Which engine is fastest most often?
2. Compute the performance gap: ratio of slowest to fastest engine for the same sequence. How large is the engine choice effect vs. sequence choice effect?
3. For each (dataset, query_file), rank all sequences by `enum_time` for each engine. How correlated are the rankings across engines? (Use Kendall's tau or Spearman's rho)
4. Does the optimal sequence depend on the engine, or is there a universally good sequence?

### Part 4: Sequence Quality Analysis (Key for M2 Design)

1. For each (dataset, query_file), identify the best sequence (lowest `enum_time`) and worst sequence per engine.
2. Compute the "penalty" of picking a random sequence vs. the best one (ratio of median enum_time to best enum_time).
3. Group query graphs by `query_vertices` (size) and `query_edges/query_vertices` (density). How does sequence selection difficulty vary with query size and density?
4. Parse each sequence string into vertex ID lists. Analyze whether certain vertex positions (early in the sequence) correlate more strongly with overall performance.

### Part 5: Summary & Recommendations

1. Summarize key findings in markdown cells.
2. Based on the analysis, recommend:
   - Which 2-3 engines to focus on for M2 evaluation
   - Whether sequence ranking is engine-dependent or engine-agnostic
   - How many candidate sequences per query graph are typically needed
   - What features of a sequence are most predictive of good performance
3. Save all processed DataFrames to `analysis/processed/` as parquet files for downstream use.
